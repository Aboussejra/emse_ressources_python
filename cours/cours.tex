\section{Objectifs et esprit du cours}

\subsection{À qui s'adresse ce cours}
\begin{leftbar}
Ce cours s'adresse à un public d'étudiants en médecine et en pharmacie, ainsi qu'à des étudiants ingénieurs, qui ne se destinent pas à devenir développeurs. L'objectif n'est donc \textbf{pas} de former des informaticiens, mais de vous permettre de \textbf{vous approprier les outils de programmation} afin de renforcer vos capacités d'analyse, en particulier sur des \textbf{données médicales}.
\end{leftbar}

\subsection{Pourquoi programmer quand on est médecin ou pharmacien ?}
Une part croissante de la pratique et de la recherche médicales repose sur des données : cohortes de patients, résultats biologiques, essais cliniques, données épidémiologiques, données de santé publique. Savoir écrire quelques dizaines de lignes de Python permet de :
\begin{enumerate}
\item charger un fichier de données (CSV, Excel) et en vérifier la qualité (valeurs manquantes, valeurs aberrantes) ;
\item calculer des indicateurs simples (effectifs, moyennes, écarts-types, proportions, corrélations) ;
\item produire des graphiques lisibles pour communiquer un résultat ;
\item automatiser un traitement répétitif, et surtout le rendre \textbf{reproductible} : le code décrit exactement ce qui a été fait sur les données.
\end{enumerate}
Autrement dit, Python est ici un \textbf{instrument de lecture critique des données}, au même titre qu'un test statistique.

\subsection{Ce que le cours n'est pas}
\begin{leftbar}
On ne cherche pas à écrire du code « propre d'ingénieur logiciel » : pas d'architecture, pas de tests unitaires, pas de gestion de projet. Un code un peu maladroit mais dont vous comprenez chaque ligne, et qui produit une analyse juste et bien commentée, vaut mieux qu'un code élégant recopié sans être compris.
\end{leftbar}

\subsection{Progression}
Le cours suit la progression suivante :
\begin{enumerate}
\item prise en main de l'environnement de travail (Google Colab) ;
\item les briques de base du langage : types de données, listes, chaînes de caractères ;
\item les bibliothèques scientifiques : \texttt{math}, \texttt{numpy}, \texttt{matplotlib} ;
\item les structures algorithmiques : tests, boucles, fonctions, récursivité ;
\item l'application à un jeu de données réel, qui constitue l'évaluation du cours (section~\ref{sec:evaluation}).
\end{enumerate}

\subsubsection{Notion de cellule}
Un notebook est une suite de \textbf{cellules} :
\begin{enumerate}
\item les cellules de \textbf{code}, qui contiennent des instructions Python. On les exécute avec \textbf{Maj+Entrée} (ou le bouton « lecture » à gauche de la cellule). Le résultat s'affiche immédiatement sous la cellule.
\item les cellules de \textbf{texte} (Markdown), qui servent à rédiger les commentaires, les titres et l'interprétation des résultats.
\end{enumerate}
\begin{leftbar}
Point important : les variables sont conservées d'une cellule à l'autre. Une variable définie dans la cellule 1 reste utilisable dans la cellule 5. En revanche, si vous exécutez les cellules dans le désordre, l'état des variables peut devenir incohérent. En cas de doute : \textbf{Tout ré-exécuter}.
\end{leftbar}

\subsection{pandas}
\subsubsection{Définition}
\begin{leftbar}
Ce module permet de manipuler des \textbf{tableaux de données} : une ligne par individu (ici, par patient), une colonne par variable, chaque colonne portant un nom. C'est la structure naturelle d'un fichier CSV ou d'un tableur, et donc l'outil de base de toute analyse de données médicales.
\end{leftbar}
Un tableau \texttt{pandas} s'appelle un \texttt{DataFrame}. Une de ses colonnes se manipule comme un tableau \texttt{numpy} : les méthodes \texttt{.mean()}, \texttt{.std()}, \texttt{.min()} et les masques booléens s'y appliquent à l'identique.

\subsubsection{Les quelques instructions à connaître}
\begin{lstlisting}[language={Python}]
import pandas as pd

df = pd.read_csv("donnees.csv")  # lecture d'un fichier au format CSV (exemple, il n'existe pas)
df.head()                        # les cinq premieres lignes
df.shape                         # (nombre de lignes, nombre de colonnes)
df.columns                       # noms des colonnes
df.isna().sum()                  # valeurs manquantes par colonne
df.describe()                    # statistiques des colonnes numeriques

df["glycemie"]                   # une colonne
df["glycemie"].mean()            # sa moyenne
df[df["glycemie"] > 1.26]        # les lignes verifiant une condition
df.groupby("tabac")["glycemie"].mean()   # comparaison de sous-groupes

df["surpoids"] = df["imc"] >= 25 # creation d'une nouvelle colonne
df.plot.scatter(x="imc", y="glycemie")   # graphique direct
\end{lstlisting}

\section{Tests, boucles et fonctions}
Trois structures suffisent à écrire la quasi-totalité des scripts de ce cours : le \textbf{test}, qui choisit entre deux options, la \textbf{boucle}, qui répète un traitement, et la \textbf{fonction}, qui donne un nom à un bloc de code pour le réutiliser. En Python, c'est l'\textbf{indentation} qui délimite le bloc concerné, et non des accolades.

Les comparaisons s'écrivent \texttt{==} (égal), \texttt{!=} (différent), \texttt{<}, \texttt{<=}, \texttt{>}, \texttt{>=}, et se combinent avec \texttt{and}, \texttt{or}, \texttt{not}. Chacune renvoie un booléen, \textbf{True} ou \textbf{False}.
\begin{leftbar}
Attention : le test d'égalité s'écrit \texttt{==}, alors que \texttt{=} est une affectation. Écrire \texttt{2=3} produit une erreur de syntaxe.
\end{leftbar}

\begin{lstlisting}[language={Python}]
mesures = [0.92, 1.31, 0.88, 1.42]
SEUIL = 1.26

# --- le test : if / elif / else ---
if mesures[0] >= SEUIL:
    print("au-dessus du seuil")
elif mesures[0] >= 1.10:
    print("zone intermediaire")
else:
    print("normale")

# --- la boucle for : le nombre de repetitions est connu d'avance ---
n = 0
for x in mesures:              # parcours direct des elements
    if x >= SEUIL:
        n = n + 1
print("effectif au-dessus du seuil =", n)

for i in range(len(mesures)):  # parcours par indice : 0, 1, 2, 3
    print(i, mesures[i])

# --- la boucle while : on repete tant qu'une condition reste vraie ---
n = 100
while n % 7 != 0:              # premier multiple de 7 superieur a 100
    n = n + 1
print(n)

# --- la fonction : def, arguments, return ---
def moyenne(valeurs):
    total = 0.0
    for x in valeurs:
        total = total + x
    return total / len(valeurs)

print(moyenne(mesures))

# assert verifie un resultat attendu et interrompt le script sinon
assert abs(moyenne([1, 2, 3]) - 2.0) < 1e-12
\end{lstlisting}

\begin{leftbar}
Deux pièges classiques. D'une part la \textbf{boucle infinie} : si la condition d'un \texttt{while} ne devient jamais fausse, le programme ne s'arrête pas ; vérifiez qu'une variable évolue bien à l'intérieur de la boucle. D'autre part la \textbf{portée des variables} : une variable créée dans une fonction est locale et n'existe pas en dehors. Pour récupérer un résultat, il faut le renvoyer avec \texttt{return}, ou l'afficher avec \texttt{print}.
\end{leftbar}

Cette page couvre le strict nécessaire. La documentation officielle, en français, suffit pour tout le reste : structures de contrôle sur \url{https://docs.python.org/fr/3/tutorial/controlflow.html}, structures de données sur \url{https://docs.python.org/fr/3/tutorial/datastructures.html}, et fonctions natives (\texttt{len}, \texttt{sum}, \texttt{sorted}, \texttt{abs}, \dots) sur \url{https://docs.python.org/fr/3/library/functions.html}.

\begin{leftbar}
Sur des données réelles, ces boucles écrites à la main sont le plus souvent remplacées par une seule instruction \texttt{numpy} ou \texttt{pandas}. Les connaître reste indispensable pour comprendre ce que ces bibliothèques calculent.
\end{leftbar}

\subsubsection{Enonc\'e}
\begin{leftbar}
Ecrire une fonction \textbf{quad} qui prend en argument trois r\'eels $a$, $b$ et $c$ et qui renvoit le nombre et le valeur des racines r\'eelles suivant l'algorithme suivant et qui les \'ecrive dans un fichier ascii appel\'e quad.txt

\begin{algorithm}
\caption{R\'esolution de $ax^2+bx+c=0$}
\begin{algorithmic}
\State $\Delta\gets b^2-4ac$
\If {$\Delta > 0$}
    \State $r1\gets \displaystyle\frac{-b-\sqrt{\Delta}}{2a}$
    \State $r2\gets \displaystyle\frac{-b+\sqrt{\Delta}}{2a}$
    \State $N \gets 2$
    \newline \textbf{print} $N,\,r1,\, r2$
\ElsIf {$\Delta == 0$}
        \State $r1\gets  \displaystyle\frac{-b}{2a}$
        \State $N \gets 1$
        \newline \textbf{print} $N,\,r1$
\Else
        \State $N \gets 0$
        \newline \textbf{print} $N$
\EndIf
\end{algorithmic}
\end{algorithm}

\section{Modalités d'évaluation}
\label{sec:evaluation}

\begin{leftbar}
L'évaluation ne porte pas sur votre capacité à restituer de la syntaxe Python, mais sur votre capacité à \textbf{vous servir de Python pour analyser un jeu de données médicales} et à en communiquer les résultats.
\end{leftbar}

\subsection{Principe}
Le point de départ est un jeu de données ouvert, dans le domaine médical ou de la santé, choisi librement parmi ceux qui vous intéressent. Quelques sources possibles :
\begin{itemize}
\item Kaggle : \url{https://www.kaggle.com/datasets}
\item UCI Machine Learning Repository : \url{https://archive.ics.uci.edu/datasets}
\item Data.gouv.fr : \url{https://data.gouv.fr/}
\end{itemize}
À partir de ces données, il s'agit de mener une analyse : les charger, les explorer, les représenter graphiquement, puis les interpréter. Les bibliothèques usuelles pour ce travail sont \texttt{pandas} (chargement et manipulation des tableaux de données), \texttt{numpy} (calculs et statistiques simples) et \texttt{matplotlib}/\texttt{seaborn} (graphiques).

\subsection{Ce qui est évalué}
\begin{enumerate}
\item savoir charger un jeu de données et le décrire : nature des variables, effectifs, valeurs manquantes ;
\item savoir produire un graphique lisible et légendé (titre, axes, unités) ;
\item savoir calculer et présenter quelques indicateurs statistiques simples, cohérents avec les graphiques ;
\item savoir interpréter : ce que les données montrent, et surtout ce qu'elles ne permettent pas de conclure ;
\item comprendre le code présenté. Un code simple et maîtrisé vaut mieux qu'un code recopié.
\end{enumerate}
La qualité logicielle du code (architecture, robustesse, style) n'est pas un critère.

\begin{leftbar}
Les modalités pratiques (forme du rendu, travail individuel ou en groupe, échéance) seront précisées plus tard.
\end{leftbar}

\section{Annexe --- exercices d'entraînement}
Les exercices suivants suivent tous la même trame : on part d'une \textbf{liste de nombres} (des mesures relevées chez des patients), on la décrit, on la nettoie, puis on la met en relation avec une autre. \item Vérifier avec \texttt{assert} que les deux approches donnent bien le même résultat.
\end{enumerate}

\subsection{Valeurs manquantes et valeurs aberrantes}
\begin{leftbar}
Sur des données réelles, une mesure peut être absente (examen non réalisé) ou fausse (erreur de saisie : une virgule oubliée). Ces deux cas faussent silencieusement toutes les statistiques.
\begin{enumerate}
\item On considère la liste suivante, où \texttt{np.nan} représente une mesure manquante :
\begin{verbatim}
[0.92, 1.05, nan, 0.88, 1.42, 0.97, 12.5, 1.68, 0.85, nan]
\end{verbatim}
Compter les valeurs manquantes, puis constater que \texttt{.mean()} renvoie \texttt{nan}.
\item Écarter les valeurs manquantes et recalculer la moyenne.
\item Repérer les valeurs aberrantes par la règle de l'écart interquartile : on calcule $Q_1$, $Q_3$, puis $IQR=Q_3-Q_1$, et on considère comme suspecte toute valeur hors de l'intervalle $[Q_1-1.5\,IQR,\;Q_3+1.5\,IQR]$.
\item Recalculer moyenne et écart-type sur les données nettoyées, et comparer.
\end{enumerate}
\end{leftbar}

\lstinputlisting[language=Python]{./codes/donnees-manquantes.py}

\begin{verbatim}

Une seule valeur aberrante sur huit suffit à rendre le résultat absurde. Regarder ses données avant de les résumer n'est pas une précaution facultative.
\end{leftbar}
